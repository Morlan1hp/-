Problem 1 [9 marks]

(a) (i) [2 marks] — the recurrence relation

Let T(n) be the total number of operations performed by TotalLightCount(n). The base case n = 0 performs a constant number of operations, say c0 (one test and one return). For n > 0 the algorithm

  • calls count(n), which is Θ(log n) by assumption, i.e. it performs c1 log2 n + c2 operations for some constants c1 > 0 and c2;
  • calls itself once, on n − 1, at cost T(n − 1);
  • performs one addition and one return, a further constant c3.

Hence, writing c = c2 + c3,

T(0) = c0,       T(n) = T(n − 1) + c1 log2 n + c   for n ≥ 1.

Suppressing the constants, which do not affect the asymptotic behaviour, the recurrence is usually written

T(0) = Θ(1),       T(n) = T(n − 1) + Θ(log n)   for n ≥ 1.

This is a decrease-by-one recursion in which the non-recursive work is logarithmic, and the argument of the logarithm is the current value of n at each level of the recursion — that is what makes the analysis in (ii) more interesting than a plain Θ(n) or Θ(n log n) guess.

(a) (ii) [3 marks] — the time complexity

Claim: T(n) ∈ Θ(n log n). This is the strongest of the three possible claims, because a Θ bound subsumes both an O and an Ω bound.

Solving the recurrence by backward substitution.

T(n) = T(n−1) + c1 log2 n + c
       = T(n−2) + c1 (log2(n−1) + log2 n) + 2c
       =  · · ·
       = T(0) + c1 ∑i=1n log2 i + c n  =  c0 + c1 log2(n!) + c n,

where the last step uses ∑i log2 i = log2 ∏i i = log2(n!). So, up to constants, the cost of the algorithm is the logarithm of a factorial.

Upper bound. Each of the n terms of the sum is at most log2 n, so log2(n!) ≤ n log2 n, and hence for every n ≥ 2

T(n) ≤ c0 + c1 n log2 n + c n  ≤  (c0 + c1 + c)  n log2 n,

because 1 ≤ n ≤ n log2 n for n ≥ 2. Therefore T(n) ∈ O(n log n).

Lower bound (using Stirling’s formula). Stirling’s formula gives n! = √(2πn) (n/e)n (1 + Θ(1/n)), so, taking base-2 logarithms,

log2(n!) = n log2 n − n log2 e + ½ log2(2πn) + Θ(1/n)  ≥  n log2 n − n log2 e.

For n ≥ 8 we have log2 n ≥ 3 > 2 log2 e ≈ 2.885, i.e. n log2 e ≤ ½ n log2 n, and so log2(n!) ≥ ½ n log2 n. Consequently

T(n) ≥ c1 log2(n!) ≥ (c1/2) n log2 n   for all n ≥ 8,

that is, T(n) ∈ Ω(n log n). Together with the upper bound this yields T(n) ∈ Θ(n log n). □

Intuition. The algorithm calls count once for each of the n + 1 tram numbers, and at least half of the numbers in [0, n] have Θ(log n) bits, so a constant fraction of those calls really do cost Θ(log n).

(b) (i) [1 mark] — completing the algorithm

The missing line is

        return 2p + q, 2q

so that the complete inductive case reads:

function TotalLightCountBitsRec(k)
    if k = 1 then
        return 1, 2
    p, q ← TotalLightCountBitsRec(k − 1)
    return 2p + q, 2q

Why. The bit strings of length k are obtained by writing a 0 or a 1 in front of each bit string of length k − 1, so there are twice as many of them: q ← 2q. Every (k−1)-bit string is used twice and both times contributes all of its own 1s, which accounts for 2p of the lit lights; in addition, each of the q strings that receives a leading 1 contributes exactly one further lit light. Hence p ← 2p + q.

(Check: the closed forms are qk = 2k and pk = k · 2k−1. For k = 3 the numbers 0, …, 7 contain 0+1+1+2+1+2+2+3 = 12 = 3 · 22 ones, as predicted.)

(b) (ii) [1 mark] — the time complexity

T(k) ∈ Θ(k).

Each invocation of TotalLightCountBitsRec makes exactly one recursive call, on k − 1, and apart from that call performs only a constant number of operations (one test, two multiplications, one addition, one return); the base case costs a constant. So

T(1) = Θ(1),       T(k) = T(k − 1) + Θ(1),

which unwinds to T(k) = Θ(1) · k = Θ(k). TotalLightCountBits merely adds one call and a constant amount of work (discarding q), so it is Θ(k) as well. The bound is Θ rather than just O because exactly k calls are made on every input — no more and no fewer — so the running time is bounded below by a constant multiple of k too. (As usual we assume that an arithmetic operation takes constant time.)

(b) (iii) [2 marks] — which algorithm is more efficient?

TotalLightCountBits is more efficient, by an exponential margin: Θ(log n) against Θ(n log n).

Let n = 2k, so k = log2 n. The integers representable with k bits are exactly 0, …, 2k−1 = 0, …, n−1, i.e. all the tram numbers except n itself; and n = 2k has exactly one light on. So the answer to the problem of part (a) is

TotalLightCountBits(log2 n) + 1.

Its cost is Θ(log n) to obtain the binary representation of n (which is what supplies k, the number of bits), plus Θ(k) = Θ(log n) for the recursion by (b)(ii), plus Θ(1) for the final increment: in total Θ(log n). By (a)(ii), TotalLightCount needs Θ(n log n) for the same answer, so it is slower by a factor of Θ(n).

The reason is that TotalLightCount re-counts the bits of every single tram number, whereas TotalLightCountBits handles a whole block of 2k−1 numbers in one step, by exploiting the fact that the k-bit numbers are two copies of the (k−1)-bit numbers.

(Check: for n = 2k the value returned is k · 2k−1 + 1 = ½ n log2 n + 1. For n = 4 this is 5, matching 0, 1, 1, 2, 1 lit lights for the trams 0–4.)

Problem 2 [8 marks]

(a) [3 marks] — a counterexample and its trace

(i) Counterexample. Take

arr = [1, 1]   and   start = 0.

Specified behaviour. No entry of arr is 0, so the network has no terminal stop, no sequence of moves can reach one, the configuration is invalid, and the procedure must return False.

Actual behaviour. IsValid_AI does not terminate: it recurses forever (in practice it crashes with a stack overflow), so it never returns False — it returns nothing at all.

(ii) Trace. The disjunction or is evaluated from left to right, so the call IsValid_AI(arr, i + dist) is made first.

  1. IsValid_AI([1,1], 0): i = 0; 0 ≤ i < 2, so no return yet; arr[0] = 1 ≠ 0; dist ← 1; evaluate the first disjunct, i.e. call …
  2. IsValid_AI([1,1], 1): i = 1; 0 ≤ i < 2; arr[1] = 1 ≠ 0; dist ← 1; evaluate the first disjunct, i.e. call …
  3. IsValid_AI([1,1], 2): i = 2 ≥ length(arr) = 2, so return False.
  4. Back in call 2: the first disjunct is False, so evaluate the second one, i.e. call …
  5. IsValid_AI([1,1], 0): identical to call 1; dist ← 1; evaluate the first disjunct …
  6. IsValid_AI([1,1], 1): identical to call 2; evaluate the first disjunct …
  7. IsValid_AI([1,1], 2): return False.
  8. Back in call 6: evaluate the second disjunct, i.e. call IsValid_AI([1,1], 0) — and the whole pattern starts again.

Calls 5–8 repeat calls 1–4 with exactly the same arguments, so the sequence of calls 0, 1, 2, 0, 1, 2, … continues forever and the top-level call never returns.

What goes wrong. The tram can oscillate 0 → 1 → 0 → 1 → …. IsValid_AI keeps no record of which stops it has already examined, so it re-explores a state it has already been in, and the recursion has no way of bottoming out. The evaluation order of or is irrelevant here: the other disjunct of call 1 is IsValid_AI([1,1], −1), which returns False at once, so whichever disjunct is attempted first the cycle is still entered.

Remark (not part of the counterexample). The same defect can also stop the algorithm from recognising a valid configuration: for arr = [0, 1, 1, 1] and start = 2 the specification demands True (the route 2 → 1 → 0 ends at the terminal stop 0), but the calls 2, 3, 2, 3, … loop forever before the backward move from stop 2 to stop 1 is ever tried.

(b) [4 marks] — a correct algorithm

The stops form a directed graph on n vertices in which stop i has at most the two out-neighbours i + arr[i] and i − arr[i] (only those that stay on the track). The question is whether a stop holding 0 is reachable from start, so we perform a depth-first search and, crucially, mark the stops already visited — which is precisely what IsValid_AI omits.

function IsValid(arr, start)
    n ← length(arr)
    if start < 0 or start ≥ n then
        return False
    visited ← new Boolean array with indices 0 … n − 1
    for i ← 0 to n − 1 do
        visited[i] ← False
    return Search(arr, start, visited)

function Search(arr, i, visited)         ▷ visited is shared by all calls
    if i < 0 or i ≥ length(arr) then
        return False                     ▷ this move leaves the track
    if visited[i] then
        return False                     ▷ this stop has been explored already
    visited[i] ← True
    if arr[i] = 0 then
        return True                      ▷ a terminal stop
    dist ← arr[i]
    if Search(arr, i + dist, visited) then
        return True
    return Search(arr, i − dist, visited)

The array visited is passed by reference, so all the recursive calls share the one array. (The two recursive calls are written as an if followed by a return rather than joined by or, so that correctness does not depend on the disjunction being evaluated lazily.)

Correctness. Search is only ever called on stops that the tram can actually move to from start, so True is returned only when a terminal stop is genuinely reachable. Conversely, if some terminal stop is reachable from start, then it is reachable by a route that visits no stop twice (any repeated stop creates a cycle which can simply be deleted from the route); depth-first search visits every vertex reachable from its origin, so that terminal stop is visited and its zero entry is detected. Finally, the algorithm always terminates, because visited[i] is set to True before the recursive calls and is never reset, so no stop is expanded twice.

(c) [1 mark] — why it runs in O(n) time

A call to Search gets past the test if visited[i] only when visited[i] is False, and it then immediately sets it to True, never to be reset. There are only n indices, so at most n calls are expanding calls of this kind. Each expanding call performs O(1) work of its own and makes at most two further calls, so at most 2n + 1 calls are made altogether, and every non-expanding call costs O(1) (one or two comparisons, then a return). Outside the search, IsValid spends Θ(n) initialising visited and O(1) elsewhere. In total Θ(n) + O(n) · O(1) = O(n). (The extra space is also Θ(n): the array visited plus a recursion stack of depth at most n.)

Problem 3 [13 marks]

(a) [2 marks] — MaxTrips

The trams run independently and each starts a new trip as soon as it finishes the previous one, so within t minutes tram i completes exactly ⌊t / time[i]⌋ trips. The maximum total is the sum of these over all trams.

function MaxTrips(time, t)
    n ← length(time)
    trips ← 0
    for i ← 0 to n − 1 do
        trips ← trips + ⌊t / time[i]⌋
    return trips

For time = [60, 40, 50, 25] and t = 50 this returns 0 + 1 + 1 + 2 = 4, as required. The function runs in Θ(n) time. Note also that MaxTrips(time, ·) is non-decreasing in t, since every ⌊t/time[i]⌋ is; parts (b) and (d) both rely on this.

(b) [3 marks] — MinTimeBruteForce

Brute force simply tries every candidate time 1, 2, 3, … in increasing order and stops at the first one that already delivers m trips.

function MinTimeBruteForce(time, m)
    t ← 1
    while MaxTrips(time, t) < m do
        t ← t + 1
    return t

Correctness. The candidates are tested in increasing order and the first one that passes the test is returned, so the value returned is by construction the smallest t ≥ 1 with MaxTrips(time, t) ≥ m, which is exactly the required minimum time T. (No time smaller than 1 need be considered, because m ≥ 1 and every trip takes at least one minute.)

Termination. Let tmin = mini time[i]. Then MaxTrips(time, tmin · m) ≥ ⌊tminm / tmin⌋ = m — the fastest tram alone already completes m trips by then — so the loop stops at some t ≤ tmin · m at the very latest.

(c) [2 marks] — complexity of MinTimeBruteForce

Let T be the value returned. The loop condition is evaluated once for each of t = 1, 2, …, T, that is T times, and each evaluation runs MaxTrips, which costs Θ(n); the rest of each iteration is O(1). So the running time is Θ(n · T) — linear in the value of the answer.

The worst case is the input that makes T largest. Since time[i] ≤ k for every i,

MaxTrips(time, k⌈m/n⌉) = ∑i ⌊k⌈m/n⌉ / time[i]⌋ ≥ n⌈m/n⌉ ≥ m,

so T ≤ k⌈m/n⌉; and this bound is attained when every tram is as slow as possible, time[i] = k for all i, for then MaxTrips(time, t) = n⌊t/k⌋, which first reaches m at t = k⌈m/n⌉. The worst-case running time is therefore

Θ(n · k⌈m/n⌉) = Θ(k (m + n)),    since m ≤ n⌈m/n⌉ < m + n,

which is Θ(k m) in the usual case m ≥ n. (Using only the cruder bound T ≤ k m of part (b) one gets O(n k m).) The important point is that the cost is proportional to the magnitude of the numbers involved rather than to the number of digits needed to write them down, so the algorithm is only pseudo-polynomial.

(d) [4 marks] — MinTimeBinarySearch

Because MaxTrips(time, ·) is non-decreasing, the predicate MaxTrips(time, t) ≥ m is monotone: it is false for every t < T and true for every t ≥ T. The candidate times therefore behave exactly like a sorted array, and we can binary search for the point at which the predicate switches from false to true instead of scanning for it. All we need is a right end of the search interval that is known to satisfy the predicate, and part (b) supplies one: tmin · m, where tmin is the shortest trip duration.

function MinTimeBinarySearch(time, m)
    n ← length(time)
    tmin ← time[0]
    for i ← 1 to n − 1 do
        if time[i] < tmin then
            tmin ← time[i]
    lo ← 1
    hi ← tmin · m              ▷ MaxTrips(time, hi) ≥ m, so T ∈ [lo, hi]
    while lo < hi do
        mid ← ⌊(lo + hi) / 2⌋
        if MaxTrips(time, mid) ≥ m then
            hi ← mid                ▷ mid is enough, so T ≤ mid
        else
            lo ← mid + 1              ▷ mid is not enough, so T > mid
    return lo

Correctness. The loop invariant is lo ≤ T ≤ hi. It holds initially, since T ≥ 1 and T ≤ tmin · m as shown in part (b). Inside the loop lo < hi, so lo ≤ mid < hi: if MaxTrips(time, mid) ≥ m then T ≤ mid by minimality of T, so setting hi ← mid preserves the invariant; otherwise monotonicity gives T > mid, so setting lo ← mid + 1 preserves it. Each iteration strictly decreases hi − lo, so the loop terminates, and on exit lo = hi, which with the invariant forces lo = T.

(On the given example time = [60, 40, 50, 25], m = 4 we get tmin = 25 and hi = 100, and the search narrows [1, 100] to [1, 50], [26, 50], [39, 50], [45, 50], [48, 50] and finally [50, 50], returning T = 50 — indeed MaxTrips(time, 50) = 4 while MaxTrips(time, 49) = 2.)

(e) [2 marks] — complexity of MinTimeBinarySearch

Computing tmin takes Θ(n). The search interval initially contains hi − lo + 1 = tmin · m ≤ k m candidate times (recall tmin ≤ k), and every iteration at least halves it, so there are at most ⌈log2(k m)⌉ + 1 iterations. Each iteration is dominated by its single call to MaxTrips, i.e. Θ(n); the rest is O(1). Hence the worst-case running time is

Θ(n) + O(n log(k m)) = O(n log(k m)) = O(n (log k + log m)),

and this is tight — Θ(n log(k m)) — in the worst case: an iteration also discards at most half of the remaining candidates, so the loop always performs ⌊log2(tmin m)⌋ or ⌈log2(tmin m)⌉ iterations — that is, Θ(log(tmin m)) of them, whatever the answer turns out to be — and tmin = k is possible.

Compared with part (c), the cost now grows with the logarithm of the numbers rather than with their magnitude: binary search replaces the Θ(k⌈m/n⌉) calls to MaxTrips made by the brute-force scan with only O(log(k m)) of them.
