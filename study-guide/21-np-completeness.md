# 第 21 章（第 22 讲）NP 完全性（了解即可）

> **考试范围**：教授原话——"NP 完全**不考**细节，最多几道是/否的基础题"。
> 但本讲的核心思想 **问题归约（problem reduction）** 对设计题非常重要：
> 遇到新问题时，想办法把它**变成一个你已经会解的问题**（排序、图遍历、最短路、DP……），解完再翻译回来。

---

## 1. 具体复杂度 vs 抽象复杂度

- **具体复杂度**（前面所有章节）：分析某个具体算法的运行时间（最好/平均/最坏），如快排最坏 O(n²)、归并 O(n log n)。
- **抽象复杂度（复杂性理论）**：问的是"**这个问题本身**有多难？"某个算法是否已经（渐近地）最优？

例：基于比较的排序问题本身需要 Ω(n log n) 次比较 ⇒ 归并排序、堆排序是渐近最优的。

## 2. "看起来很像，难度天差地别"

| 容易（有多项式算法） | 困难（不知道多项式算法） |
|---|---|
| **SPATH**：a 到 b 是否有长度 **≤ k** 的简单路径？ | **LPATH**：a 到 b 是否有长度 **≥ k** 的简单路径？ |
| **欧拉回路 EUL**：经过每条**边**恰好一次 | **哈密顿回路 HAM**：经过每个**结点**恰好一次 |
| 2-着色（二分图判定，DFS） | **3COL**：能否用 3 种颜色着色 |
| 普通差分约束 DC | 模 m 的差分约束 DCₘ |

其他著名难题：
- **SAT**：给定命题逻辑公式 φ，它是否可满足？
- **SUBSET-SUM**：正整数集合 S 中是否有子集的和恰好为 t？
- TSP、0/1 背包（判定版）。

## 3. 多项式时间可验证
上面这些难题有一个共同点：**如果有人给出一个解，我们能很快（多项式时间）检查它对不对**。
例如给出一个 3-着色方案，逐条边检查两端颜色是否不同即可。
⇒ 难以**求解**，但容易**验证**。规划、调度、设计、信息检索、网络、博弈中有大量这样的问题。

## 4. P 与 NP
- **非确定性算法**：第 1 阶段"猜"一个候选解 S；第 2 阶段用确定性算法检查 S 是否是实例 I 的解。
  若对每个"是"实例都能（通过某个猜测）回答"是"，就说它解决了该问题。
- **P**：能被**确定性**算法在多项式时间内解决的**判定问题**的类。
- **NP**：能被**非确定性**多项式算法解决的问题的类（= 解可以在多项式时间内验证）。
- 显然 **P ⊆ NP**。**P = NP 吗？** 不知道——这是计算机科学最重要的未解问题（千禧年七大数学难题之一，奖金一百万美元）。

## 5. 问题归约（Problem Reduction）

**粗略的想法**：问题 P 的每个实例 p 都能**忠实地**（且不费太多力气地）翻译成问题 Q 的实例 q，
且从 q 的解能直接得到 p 的解。于是解 p 只需：①翻译成 q；②用 Q 的算法解 q；③把结果翻译回来。
⇒ **P 不比 Q 难**。

我们已经见过的归约：
- 划分问题 → 子集和（第 4 章）
- 调度问题 → 拓扑排序（第 7 章）
- 座位安排 → 图着色（第 6 章）
- 硬币行 → DAG 最长路径（第 17 章）
- 元素唯一性 → 排序（第 13 章）

### 精确定义
A **多项式时间可归约**到 B，记作 **A ≤ₚ B**：存在多项式时间可计算的函数 f，使对所有输入 w，
**w ∈ A ⇔ f(w) ∈ B**。

**定理**：若 A ≤ₚ B 且 B ∈ P，则 A ∈ P。

### 讲义例子：差分约束
- **DC**（普通算术）：一组形如 x − y ∈ [k₁, k₂] 的约束，求解或判定无解。
  例：x − y ∈ [10, 11]，y − z ∈ [7, 8]，x − z ∈ [1, 4] 无解。
  有快速算法：把约束改写成 x − y ≤ 11、y − x ≤ −10 …，建一个带权图，问题化为"**图中是否有负权环**"，用 **Bellman-Ford** 求解。
- **DCₘ**（模 m 算术，计算机实际用的就是 m = 2³² 或 2⁶⁴）：上面的例子在模 16 下有解 x = 11, y = 0, z = 8。
  看起来只是小改动，但可以把 **3COL 归约到 DCₘ**：每个结点 xᵢ 加约束 xᵢ − x ∈ [0, 2]（三种颜色），
  每条边 (i, j) 加约束 xᵢ − xⱼ ∈ [1, m − 1]（颜色不同）。图可 3-着色 ⇔ 约束有解。
  ⇒ DCₘ 至少和 3COL 一样难 ⇒ **不必再浪费时间找它的高效算法**。这就是复杂性理论的实用价值。

## 6. NP 难与 NP 完全
- **B 是 NP 难（NP-hard）**：每个 NP 中的问题都能多项式归约到 B。
- **B 是 NP 完全（NP-complete）**：① B ∈ NP，且 ② B 是 NP 难的。
- **定理**：若某个 NP 完全问题属于 P，则 **P = NP**。⇒ 所有 NP 完全问题"同生共死"。
- NP 完全问题：SAT、SUBSET-SUM、3COL、LPATH、HAM……成千上万个实际问题。目前不知道本质上比穷举更好的算法。

## 7. 遇到 NP 完全问题怎么办
- **伪多项式问题**：如 SUBSET-SUM、KNAPSACK，Θ(nW) 的 DP 在数字不太大时完全够用。
- **SAT 求解器**：靠精巧的工程一点点推进边界。
- **近似算法**：放弃完美，追求足够好。
- **与困难共存**：坏实例在实际中可能根本不会出现。
- 更糟的情况：有些实际重要的问题**根本没有算法**（不可判定，如停机问题）。

## 可能的是/否题（自测）

1. P ⊆ NP。
2. 已经证明 P ≠ NP。
3. 哈密顿回路问题是 NP 完全的。
4. 欧拉回路问题是 NP 完全的。
5. 若 A ≤ₚ B 且 A 很难，则 B 也至少一样难。
6. 若某个 NP 完全问题有多项式算法，则所有 NP 问题都有多项式算法。
7. NP 中的问题，其"是"实例的解可以在多项式时间内验证。
8. 0/1 背包的 Θ(nW) 动态规划算法是多项式时间算法（相对于输入长度）。
